## Boot path — grub generator rework — STANDS, mechanics confirmed from source

Generator = `generate_grub_cfg_body()` in `distributions/ROCKNIX/config/functions`
(read 2026-08-28). Confirmed: per-device entries with `$menuentry_id_option
'rpflip2'`, `savedefault`, explicit `devicetree`; **the `abl_dev` block runs AFTER
`load_env` and overrides `saved_entry`** whenever `fdtdump --prop model --set
abl_model` succeeds AND the model matches (`Retroid Pocket Flip2` → `rpflip2`).
grub.cfg is a build-time STATIC file; `devices/SM8250/bootloader/update.sh`
(byte-identical 20260801→next) **unconditionally overwrites both twins** with it,
installs grubenv only if missing, and stages `rocknix_abl/*` payload files to
`/flash/rocknix_abl/` — **the in-place update never flashes the ABL partition**, so
whether `fdtdump` succeeds is a property of the ABL the operator last
fastboot-flashed (rocknix-abl package bumped 1.1.6→1.1.8 between tags, reaches the
rig only via a manual reflash). The empirical answer arrives with the first nightly
boot: menu default lands on the device entry despite `saved_entry=etk-gtk-test`
dangling ⇒ abl_dev fired; menu falls to the FIRST entry (rp5 — the 20260801
"grubenv seeded to rp5" incident is exactly this shape) ⇒ fdtdump failed.

**Counter (ships in ETK install.sh, decided against the live artifact):** STEP 6.4's
twin-entry writer, when `KERNEL_DEPLOY_MODE=default` AND the live grub.cfg contains
the Flip-2 match line, rewrites `set abl_dev="rpflip2"` → `set abl_dev="etk-gtk-test"`
(auto-detect then selects OUR entry; stock stays one menu pick away; panic=10 crash
reboots return to the GTK kernel). Mode=test restores the stock line. **LANDED
2026-08-28 (etk b9e5495):** the counter lives in STEP 6.4's twin-writer; the surface
is the `KERNEL_OK` verdict's new `abl=absent|etk|stock` field with a RED warn on
default+stock (implemented there rather than in STEP 6.65 — same install-time
surface, less surgery). `tools/test_grub_abl.sh` = the harness (13/13: transforms
extracted verbatim, no-op on the real 20260801 artifact, patch/restore idempotent
on the synthesized new-generator fixture, rig-BusyBox leg byte-identical). Inert on
20260801 (no block to match). Known window: an OS update regenerates grub AFTER
install day — osguard's Phase B replays only the banked ETK entry block, not the
abl counter, so until the next install.sh run the failure direction is SAFE (stock
boots); the ledger's stack field is the runtime tell.
