## SM8250-specific upstream changes

### 1. `sm8250: gpu improvements` — the headline (commit `3f9e7f64`, 2026-08-02)

Replaces `9998-gpu-opp-table.patch` (old 650–800 MHz extension, 800 @ NOM_L1) with
`9998-gpu-tuning.patch` (166 lines, `sm8250.dtsi` only):

- **Frequency ladder 305 → 925 MHz** (adds 700/725/750/800/855/905/925 at proper
  TURBO/TURBO_L1 regulator levels — the old patch's 800 MHz @ NOM_L1 undervolt is gone).
  KonaBess-matched, speedbin-gated (`opp-supported-hw`).
- **ACD enabled** (`qcom,opp-acd-level` on every OPP + `qcom,qmp = <&aoss_qmp>` on the
  GMU node). Adaptive Clock Distribution changes the electrical operating point at
  EVERY frequency, not just the new ones.
- **GPU→DDR bandwidth voting** (`interconnects` gfx-mem + `opp-peak-kBps` per OPP,
  matched to stock Android votes). Mainline previously never voted GPU memory bandwidth
  on this SoC — a real perf lever, and a real battery cost at idle (upstream's own note).
- Companion quirk: `bin/gpu_overclock` now offers 587/650/700/725/750/800/855/905/925.

**Lane impact:** this is **DTS-only** — it lands in the DTB
(`/boot/grub/sm8250-retroidpocket-flip2.dtb`, shipped by the OS update), NOT in our
kernel Image. Staging still tracks it (03-device patch swap + `dts-device/` +
groundtruth DTB refresh) for reconstruction parity.

**Tuning impact:** the whole stability baseline moves with the chassis (ACD + new
clocks + bandwidth votes ride the DTB regardless of which kernel Image boots). The K1
cold-boot gate and the combined confirmation block are the controls — do not credit or
blame any dial across the 20260801→20260901 boundary. The ETK POWER-tab "OPP cap
800 MHz" doctrine is now stale upstream; 855/905/925 are candidate EXPERIMENTAL rungs
for a post-0.9.0 A/B lane (thermal budget on a fanless shell is the open question).
Bandwidth voting is a candidate mechanism for the sawtooth/pack-front hunts — ledger
will show it as a chassis effect, not a dial.

`quiet rootwait console=tty0 video=efifb:off gpt`. The ETK grub twin entries must

### 3. Kernel config: LSUI flips ON upstream

Net `linux.aarch64.conf` drift vs 20260801 is toolchain stamps plus
`CONFIG_AS_HAS_LSUI=y` / `CONFIG_ARM64_LSUI=y` — upstream CI's binutils now passes the
LSUI probe, so **stock 20260901 ships ARM64_LSUI compiled IN** (still inert on this
silicon — A77/A55 have no FEAT_LSUI). `build_712.sh` force-disables ARM64_LSUI for
20260801 parity; **the 20260901 lane must drop that line** (the refreshed rig
`/proc/config.gz` ground truth will carry `=y`, and our binutils 2.46 passes the probe).

### 4. `regulatory.db` built into the kernel image (commit `3dcb444c`, 2026-08-06)

`packages/linux/package.mk` now appends `regulatory.db regulatory.db.p7s` to
CONFIG_EXTRA_FIRMWARE whenever `CONFIG_CFG80211=y` (fixes wifi stuck in domain 00 /
5 GHz no-IR — the firmware symlink dangles at cfg80211 init). Consequences:

- `staging/external-firmware/` grows to **8 blobs** (6 Qualcomm + `regulatory.db` +
  `regulatory.db.p7s`, wireless-regdb `2026.05.30`). Pull both from the updated rig's
  `/usr/lib/firmware/`, same flow as the six.
- Stock image size shifts (~+7 KB) — new stock-exact byte target from the new
  groundtruth `KERNEL.stock-20260901`.
- Post-boot verify bonus: `iw reg get` should finally show a real regulatory domain —
  a user-visible 5 GHz wifi win to record.

## Boot path — grub generator rework (affects ETK STEP 6.4 / 6.65)

Three commits rewrote `generate_grub_cfg_body` (`405240bf` + `b5a7a06d` merged
2026-08-15/16, fixed by `ff8058e3` PR #3219 2026-08-20). **None of this exists in
20260801** — it all arrives with the 20260901 update's regenerated `grub.cfg`:

1. Per-device menuentries now carry `$menuentry_id_option '<short>'` ids (Flip 2 =
   `rpflip2`), `savedefault`, and explicit `devicetree /boot/grub/<dtb>.dtb`.
2. **NEW: ABL model auto-select that runs AFTER — and overrides — `saved_entry`:**

   ```
   set abl_dev=
   if fdtdump --prop model --set abl_model; then
     if [ "${abl_model}" = "Retroid Pocket Flip2" ]; then set abl_dev="rpflip2"; fi
     ...
   fi
   if [ -n "${abl_dev}" ]; then set default="${abl_dev}"; set timeout=2; fi
   ```

   The Flip 2 IS in the match table (`config.xml`: `full="Retroid Pocket Flip2"` →
   `short="rpflip2"`). If the ABL hands grub a model-matching FDT (the multi-device
   auto-detect this feature exists for), **every boot defaults to the stock entry
   regardless of `saved_entry=etk-gtk-test`** — which breaks (a) the promoted-kernel
   auto-boot and (b) `panic=10` crash-reboot returning to the GTK kernel. Failure
   direction is SAFE (stock boots), but the daily-driver contract silently dissolves.

   **Counter-plan (decide on the artifact, not the pipeline):** after the OS update,
   read the regenerated `grub.cfg`; if the block is present, STEP 6.4's twin-entry
   writer rewrites the Flip-2 match line to `set abl_dev="etk-gtk-test"` (auto-detect
   then selects OUR entry; stock stays one menu pick away), and STEP 6.65's drift
   tripwire learns to flag an unpatched `abl_dev` block. Confirm with one cold boot
   whether `fdtdump` actually succeeds on this ABL before concluding either way.
3. `devices/SM8250/bootloader/update.sh` is **unchanged** — the documented OS-updater
   trap (kernel slot clobber + grub regeneration + grubenv reseed) behaves exactly as
   before; the existing post-update verification protocol stands.
